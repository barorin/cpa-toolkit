# 監査調書の作成

会社の基礎資料(試算表、契約書、議事録、規程等)を用いて監査調書のドラフトを作成するスキル。

## モデル振り分け(このスキルの核心)

| 工程                          | 実行者                                         | 理由               |
| ----------------------------- | ---------------------------------------------- | ------------------ |
| ①目的・範囲の確認、資料の読解 | メイン(高推論モデル)                           | 専門的読解         |
| ②手続の設計・実施・結論の導出 | メイン(高推論モデル)                           | 監査上の中核的推論 |
| ③調書フォーマットへの整形     | **report-writer エージェント(低コストモデル)** | 整形は判断不要     |
| ④最終レビュー                 | メイン(高推論モデル)                           | 品質担保           |

大量資料の機械的な突合・集計(明細と残高の照合等)が必要な場合のみ、その部分を data-processor エージェント(低コストモデル)に委譲してよい。

## 手順

### ① 前提確認(メイン)

利用者に確認する(不在時は合理的な前提を置き調書冒頭に明記): 調書の目的(どの監査要点・アサーションに対応するか)、対象科目・期間、重要性の基準値、事務所の調書様式の有無(あれば添付を依頼)、詳細テストか分析的手続か。提供された基礎資料をすべて読み、資料の一覧(資料名・作成者・日付)を作る。

### ② 手続の実施(メインで実施 — 委譲しない)

- 監査要点に対応する手続を設計し、提供資料の範囲で実施する(突合、再計算、分析的手続、閲覧)。
- 発見事項は「事実(資料の記載)→評価(基準・重要性への当てはめ)」を分離して整理する。
- 会計基準・監査基準に言及する場合は accounting-consult スキルと同じ出典ルール(基準名・号数・項番号、Web検索による最新性確認)に従う。
- **資料が不足していて実施できない手続は、実施したことにせず「未実施(必要資料: 〇〇)」として整理する。**
- 結論を導出する(例外事項の有無、追加手続の要否を含む)。

### ③ 調書整形(report-writer に委譲)

**`assets/workpaper-template.md` をコピーして埋める方式で作成させる**(config に事務所様式が登録されていればそちらを優先。記載ルールは `references/workpaper-format.md`)。以下の引き渡し資料とともに report-writer を起動する: 調書の目的・範囲・重要性、資料一覧、実施した手続と結果(数値・突合結果を含む)、発見事項、結論、未実施手続と必要資料、基準の出典。「引き渡した結論・数値のみを使い、不足箇所は【要確認】でマークする」ことを指示する。出力形式は利用者の指定(標準: docx)。

### ④ 最終レビュー(メイン+専任エージェント)

整形された調書を読み、(a) 手続・結果・結論の整合(結論が手続結果から導けるか)、(b) 数値の転記正確性、(c) 【要確認】・未実施事項が消されていないか、を検証する。基準の引用がある場合は standards-checker エージェントに原文突合を委譲する。さらに reviewer エージェント(高推論モデル)による独立のコールドレビューを実施し、High/Medium の指摘に対応してから納品する。

## 注意(重要)

- 本スキルの成果物は**調書のドラフト(作成補助)**であり、監査手続の実施・調書の最終化・監査上の結論は監査人自身の責任で行うものである旨を、納品時に必ず一言添える。
- AIが実施できるのは提供された資料の範囲内の検討のみである。実査・立会・確認・質問など実施できない手続を「実施した」と記載することは絶対にしない。
- クライアント情報を含むため、成果物の保存先・共有範囲は利用者の指示に従う。

## 共通運用ルール

- **設定ファイル**: 作業開始前に `${CLAUDE_PLUGIN_DATA}/config.json`(環境変数未定義なら `~/.claude/cpa-toolkit-data/config.json`)を読む。設定済みの項目(適用基準の既定、重要性方針、様式、閾値、想定読者等)は確認質問を省略する。恒常的に使えそうな新しい設定を確認したら、利用者の同意を得て設定ファイルに保存する(初回セットアップは cpa-setup スキル)。
- **委譲の例外**: 対象が小さい場合(目安: データ数百件以下、文書数ページ、単一の軽い論点)は、サブエージェント委譲のオーバーヘッドの方が大きいため、メインで直接実施してよい。ただし品質工程(最終レビュー・引用突合)は省略しない。
- **Gotchas を育てる**: このスキルの利用中に新しい失敗・つまずきがあったら、下の Gotchas に追記する(CLI では直接編集、Cowork ではチャットで改訂を依頼するよう利用者に一言添える)。

## Gotchas(実際に踏んだ罠を追記して育てる)

- 転記時に千円単位と円単位が混在する事故が多い。テンプレートに単位を明記し、レビューで単位を必ず確認する。
- 監査基準報告書の項番号を記憶で書かない(改正で番号がずれる)。standards-checker の突合対象に含める。
- report-writer がテンプレートの【要確認】を気を利かせて埋めてしまうことがある。引き渡し時に「埋めるな」と明示し、レビューで【要確認】の残存を確認する。
- 「閲覧した」「突合した」等の手続動詞は、実際にAIが実施できた行為(提供資料の範囲内)に限って使う。
