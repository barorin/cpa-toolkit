# 仕訳データ分析(Journal Entry Testing)

仕訳データの機械的テストと異常項目の専門的評価を行うスキル。

## モデル振り分け(このスキルの核心)

| 工程                      | 実行者                                          | 理由                     |
| ------------------------- | ----------------------------------------------- | ------------------------ |
| ①データ受領・テスト設計   | メイン(高推論モデル)                            | リスク評価に基づく判断   |
| ②前処理・集計・テスト実行 | **data-processor エージェント(低コストモデル)** | コード実行主体で判断不要 |
| ③抽出項目の解釈・評価     | メイン(高推論モデル)                            | 監査上の専門的判断       |
| ④結果レポート整形         | **report-writer エージェント(低コストモデル)**  | 生成量が多く判断不要     |

## 実行環境

スクリプト実行前に依存を確認する(必須: pandas, numpy):

```bash
python -c "import pandas, numpy" || pip install pandas numpy
```

任意: openpyxl(Excel入力時)、jpholiday(祝日判定。未導入時は土日のみの判定になり summary.json に注記される)。不足したまま実行してもスクリプトが具体的なインストールコマンドを案内する。
pip が使えない環境では `uv run --with pandas --with numpy scripts/jet_tests.py ...` でも実行できる。

## 手順

### ① テスト設計(メイン)

データ(CSV/Excel等)の項目を確認し、利用者に以下を確認する(不在時は標準設定で進め前提を明記): 分析目的(不正リスク対応/期中レビュー/異常検知)、対象期間、重要性の基準値、特に懸念しているリスク。目的とデータ項目に応じて `references/analysis-tests.md` から実行するテストを選定し、閾値を決める。

### ② 実行(data-processor に委譲)

**テストは同梱スクリプト `scripts/jet_tests.py` で実行する。ロジックを毎回書き直さない。** Agent ツールで data-processor を起動し、以下を渡す: データファイルのパス、`scripts/jet_tests.py` の絶対パス、実行するテストと閾値(config の jet_defaults があればそれを既定に)、「まず列名を確認して colmap.json(論理名→実列名の対応)を作成し、スクリプトを実行し、A_completeness.md と summary.json の内容を報告する」指示。スクリプトの使い方・列の論理名はスクリプト冒頭の docstring に書いてある。スクリプトが対応していない特注テストが必要な場合のみ、追加分を別スクリプトとして書かせる(jet_tests.py 自体は改変しない)。

### ③ 評価(メインで実施 — 委譲しない)

data-processor のサマリーと抽出ファイルを読み、以下を行う:

- 完全性チェック結果の確認(貸借不一致・期間の欠落があれば利用者に報告し、原因確認を優先する)
- 抽出項目を重要性・リスクの観点で選別し、フォローアップすべき仕訳を特定する(仕訳番号・金額・理由を明示)
- 抽出パターンから読み取れる不正シナリオ・内部統制上の懸念を評価する
- 追加で実行すべきテストがあれば②に戻って data-processor に依頼する

### ④ レポート(report-writer に委譲、または省略)

利用者がレポートを求める場合のみ、③の評価結果・②の実行記録・出力ファイル一覧を引き渡し資料にまとめて report-writer に整形させ、メインで最終確認して納品する。会話内での報告で足りる場合は委譲せずメインが簡潔に報告する。

## 注意

- 元データは変更しない。抽出・加工結果はすべて別ファイル。
- 抽出された仕訳は「異常の候補」であり不正の証拠ではない。評価では断定を避け、推奨するフォローアップ手続(証憑突合、担当者への質問等)を付す。
- 個人名・取引先名等が含まれるデータの扱いに留意し、レポートへの記載は必要最小限にする。

## 共通運用ルール

- **設定ファイル**: 作業開始前に `${CLAUDE_PLUGIN_DATA}/config.json`(環境変数未定義なら `~/.claude/cpa-toolkit-data/config.json`)を読む。設定済みの項目(適用基準の既定、重要性方針、様式、閾値、想定読者等)は確認質問を省略する。恒常的に使えそうな新しい設定を確認したら、利用者の同意を得て設定ファイルに保存する(初回セットアップは cpa-setup スキル)。
- **委譲の例外**: 対象が小さい場合(目安: データ数百件以下、文書数ページ、単一の軽い論点)は、サブエージェント委譲のオーバーヘッドの方が大きいため、メインで直接実施してよい。ただし品質工程(最終レビュー・引用突合)は省略しない。
- **Gotchas を育てる**: このスキルの利用中に新しい失敗・つまずきがあったら、下の Gotchas に追記する(CLI では直接編集、Cowork ではチャットで改訂を依頼するよう利用者に一言添える)。

## Gotchas(実際に踏んだ罠を追記して育てる)

- 日付列がExcelシリアル値・和暦・8桁数値(20260331)のことがある。colmap作成時に必ず実データを目視確認する。
- 文字コードは Shift-JIS(CP932)が多い。jet_tests.py は自動判定するが、化けたらまず文字コードを疑う。
- 借方/貸方の持ち方は「2列」「1行2レコード」「金額+貸借区分」の3パターンがある。伝票単位の貸借一致(A1)が大量に不一致なら、データの持ち方の解釈を疑う。
- 複合仕訳・消費税の自動仕訳で行数と伝票数を混同し、件数を過大報告しがち。件数は伝票単位(entry_id)で数える。
- 金額を float のまま集計すると丸め誤差が出る。スクリプト外で追加集計する場合も整数(円)で扱う。
