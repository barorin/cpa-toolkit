# 監査サンプリング

母集団からの監査サンプルの設計・抽出・文書化を行うスキル。

## モデル振り分け

| 工程                    | 実行者                                   | 理由                   |
| ----------------------- | ---------------------------------------- | ---------------------- |
| ①サンプリング設計       | メイン(高推論モデル)                     | リスクに基づく判断     |
| ②母集団の検証と抽出実行 | **data-processor(低コストモデル)**       | ほぼ全編コード実行     |
| ③抽出結果の確認・文書化 | メイン+**report-writer(低コストモデル)** | 確認は軽く、整形は委譲 |

## 実行環境

スクリプト実行前に依存を確認する(必須: pandas, numpy):

```bash
python -c "import pandas, numpy" || pip install pandas numpy
```

任意: scipy(size-attr のみ)、openpyxl(Excel入力時)。不足したまま実行してもスクリプトが具体的なインストールコマンドを案内する。
pip が使えない環境では `uv run --with pandas --with numpy scripts/sampling.py ...` でも実行できる。

## 手順

### ① 設計(メイン)

利用者に確認する(不在時は合理的な設定で進め前提を明記): テストの目的(実証手続/内部統制の運用評価)、母集団の定義、手法(金額単位抽出MUS/無作為抽出/属性サンプリング/特定項目抽出との併用)、パラメータ(実証: 許容誤謬・予想誤謬・重要性基準値、統制: 許容逸脱率・予想逸脱率・信頼水準)。パラメータからサンプル件数を算定し、根拠(`references/sampling-methods.md` 参照)を示す。特定項目(高額・リスク項目)を先に切り出す場合は残余母集団を明確にする。

### ② 実行(data-processor に委譲)

**サンプルサイズ算定と抽出は同梱スクリプト `scripts/sampling.py` で実行する。ロジックを毎回書き直さない。** 母集団ファイルのパス、`scripts/sampling.py` の絶対パス、手法・パラメータ(config の sampling_defaults があればそれを既定に)を渡す。使い方はスクリプト冒頭の docstring のとおり(size-attr / size-mus / mus / random)。指示に含めること: スクリプトが表示する母集団の件数・合計をGL残高等と突合してから抽出を確定する、**シードは日付等から決めて記録する(再現可能性)**、出力される sample_list.csv / sampling_record.md / excluded.csv を報告する。層化など特注の抽出が必要な場合のみ追加処理を書かせる。

### ③ 文書化(メイン → report-writer)

抽出結果を確認し(件数・カバレッジ・特定項目との重複がないか)、文書化が必要なら「目的・母集団・手法・パラメータ・算定根拠・シード・抽出リスト」を引き渡して report-writer に整形させる。監査調書にする場合は audit-workpaper スキルの様式に従う。

## 注意

- サンプル件数を「いつもの25件」のような慣行で決めず、パラメータからの算定根拠を残す(利用者が件数を直接指定した場合はそのまま従い、指定による旨を記録する)。
- 抽出後の評価(誤謬の推定・母集団への影響)まで求められた場合、誤謬の集計は data-processor、母集団全体への波及の評価はメインで行う。

## 共通運用ルール

- **設定ファイル**: 作業開始前に `${CLAUDE_PLUGIN_DATA}/config.json`(環境変数未定義なら `~/.claude/cpa-toolkit-data/config.json`)を読む。設定済みの項目(適用基準の既定、重要性方針、様式、閾値、想定読者等)は確認質問を省略する。恒常的に使えそうな新しい設定を確認したら、利用者の同意を得て設定ファイルに保存する(初回セットアップは cpa-setup スキル)。
- **委譲の例外**: 対象が小さい場合(目安: データ数百件以下、文書数ページ、単一の軽い論点)は、サブエージェント委譲のオーバーヘッドの方が大きいため、メインで直接実施してよい。ただし品質工程(最終レビュー・引用突合)は省略しない。
- **Gotchas を育てる**: このスキルの利用中に新しい失敗・つまずきがあったら、下の Gotchas に追記する(CLI では直接編集、Cowork ではチャットで改訂を依頼するよう利用者に一言添える)。

## Gotchas(実際に踏んだ罠を追記して育てる)

- 母集団の合計とGL残高の不一致のまま抽出しない。sampling.py が表示する件数・合計の突合が最初の関門。
- マイナス・ゼロ金額はスクリプトが自動除外して excluded.csv に出す。除外分の扱い(別途検討)を忘れず文書化する。
- 特定項目(高額)を先に切り出した場合、サンプルサイズ算定は残余母集団の金額で行う。全体金額のまま計算しない。
- シードを記録し忘れると再現できない。sampling_record.md が出力されたことを必ず確認する。
