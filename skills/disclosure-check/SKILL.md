# 開示チェック

財務諸表・注記・開示書類を、機械的検証と専門的検討の二段階でチェックするスキル。

## モデル振り分け

| 工程                        | 実行者                                             | 理由                     |
| --------------------------- | -------------------------------------------------- | ------------------------ |
| ①範囲・チェックリストの確定 | メイン(高推論モデル)                               | 判断                     |
| ②機械的チェック             | **data-processor / doc-extractor(低コストモデル)** | 照合・計算・転記チェック |
| ③記載の十分性の検討         | メイン(高推論モデル)                               | 基準への当てはめ         |
| ④結果の文書化               | **report-writer(低コストモデル)**                  | 整形                     |

## 手順

### ① 範囲確定(メイン)

対象書類(計算書類/有価証券報告書/四半期・中間/会社法・金商法の別)、適用基準(日本基準/IFRS)、会社の適用している表示方法(千円/百万円)を確認する。事務所や日本公認会計士協会等のチェックリストが提供されればそれを使い、なければ当期の会社の状況(新基準適用、組織再編等)から重点項目をメインが設計する。

### ② 機械的チェック(低コストエージェントに委譲)

対象書類のファイルを渡し、以下を実行させる:

- 縦計・横計・内訳と合計の一致、単位・端数処理の整合
- 財務諸表本表と注記の数値の相互整合(例: 注記の内訳合計と本表残高)
- 前期数値の前期開示との一致(比較情報の転記チェック)
- 定型的な記載事項の有無(継続企業、会計方針、後発事象等のセクションの存在確認)
- 結果は「一致/不一致(差額)/確認不可」の一覧で出力

### ③ 十分性の検討(メインで実施 — 委譲しない)

- 会社の当期の取引・事象(minutes-review 等の結果があれば活用)に照らし、**開示すべきなのに開示がない項目**を検討する(機械的チェックでは検出できない領域)。
- 個別の注記の記載内容が基準の要求事項を満たすかを、重要性を踏まえて検討する。基準への言及は accounting-consult スキルの出典ルールに従い、必要に応じ standards-checker で引用を突合する。
- 指摘は「不備(基準違反の可能性)/改善提案/軽微」に区分する。

### ④ 文書化(report-writer → メインでレビュー)

指摘一覧(箇所・内容・根拠基準・区分)に整形させ、メインで最終確認して納品する。

## 注意

- 開示の適正性の最終判断は作成者(経営者)・監査人の責任である旨を付す。
- XBRLや様式の細則レベルの検証はこのスキルの対象外であることを明示する(求められたら範囲を協議)。

## 共通運用ルール

- **設定ファイル**: 作業開始前に `${CLAUDE_PLUGIN_DATA}/config.json`(環境変数未定義なら `~/.claude/cpa-toolkit-data/config.json`)を読む。設定済みの項目(適用基準の既定、重要性方針、様式、閾値、想定読者等)は確認質問を省略する。恒常的に使えそうな新しい設定を確認したら、利用者の同意を得て設定ファイルに保存する(初回セットアップは cpa-setup スキル)。
- **委譲の例外**: 対象が小さい場合(目安: データ数百件以下、文書数ページ、単一の軽い論点)は、サブエージェント委譲のオーバーヘッドの方が大きいため、メインで直接実施してよい。ただし品質工程(最終レビュー・引用突合)は省略しない。
- **Gotchas を育てる**: このスキルの利用中に新しい失敗・つまずきがあったら、下の Gotchas に追記する(CLI では直接編集、Cowork ではチャットで改訂を依頼するよう利用者に一言添える)。

## Gotchas(実際に踏んだ罠を追記して育てる)

- 本表(百万円)と注記(千円)など単位が混在する書類の照合で、単位換算ミスによる誤検出/見逃しが起きる。照合前に単位を正規化する。
- 前期数値は当期の組替表示が入ることがある。「前期開示との不一致」が組替によるものか誤りかを区別する。
- セグメント注記と本表の照合(調整額を含む)は漏れやすい定番。機械的チェックの指示に明示的に含める。
- 四半期・中間の簡素化された開示要求を年度の要求と混同しない。
