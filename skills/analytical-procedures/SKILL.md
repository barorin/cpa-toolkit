# 分析的手続

試算表・月次推移等から増減分析・比率分析を行い、期待値との乖離を識別・評価するスキル。

## モデル振り分け

| 工程                        | 実行者                             | 理由                 |
| --------------------------- | ---------------------------------- | -------------------- |
| ①分析の設計・期待値の設定   | メイン(高推論モデル)               | 事業理解に基づく判断 |
| ②集計・比率計算・グラフ作成 | **data-processor(低コストモデル)** | コード実行主体       |
| ③乖離の識別と評価           | メイン(高推論モデル)               | 専門的推論           |
| ④レポート整形               | **report-writer(低コストモデル)**  | 整形は判断不要       |

## 手順

### ① 設計(メイン)

利用者に確認する(不在時は標準設定で進め前提を明記): 分析の位置づけ(リスク評価手続/実証手続としての分析的手続/最終分析)、対象科目・期間、重要性の基準値、許容可能な乖離額(実証手続の場合は必須)。事業内容・既知の環境変化(値上げ、新規出店、為替等)を踏まえて**科目ごとの期待値(期待される増減の方向・概算額)と、その根拠を分析実行前に明文化する**。数値を見てから期待値を後付けしない。

### ② 実行(data-processor に委譲)

データファイルのパスと以下の指示を渡す: 前期比・前年同月比・月次推移の集計、主要比率(売上総利益率、営業利益率、回転期間(売上債権・棚卸資産・仕入債務)、その他科目に応じた比率)の算定、指定があれば季節性を考慮した趨勢分析、グラフ(推移・構成比)の作成、結果のファイル出力。

### ③ 評価(メインで実施 — 委譲しない)

- ①の期待値と②の実績を比較し、許容可能な乖離を超える項目を識別する。
- 乖離項目ごとに考えられる原因(事業要因/会計方針の変更/誤謬/不正の可能性)を挙げ、追加で確かめるべき事項(質問・証憑・仕訳の深掘り)を特定する。乖離の説明を安易に受け入れず、説明と整合する裏付けの要否を検討する。
- 仕訳レベルの深掘りが必要なら journal-analysis スキルに接続する。

### ④ レポート(report-writer に委譲、または省略)

文書化が必要な場合、期待値・実績・乖離・評価・追加手続を引き渡し資料にまとめて report-writer に整形させ、メインで最終確認して納品する。

## 注意

- 実証手続としての分析的手続の場合、データの信頼性(情報の出所・作成過程)の検討を省略しない。
- 期待値の設定根拠を必ず文書に残す(監査調書化する場合は audit-workpaper スキルの出典ルールに従う)。

## 共通運用ルール

- **設定ファイル**: 作業開始前に `${CLAUDE_PLUGIN_DATA}/config.json`(環境変数未定義なら `~/.claude/cpa-toolkit-data/config.json`)を読む。設定済みの項目(適用基準の既定、重要性方針、様式、閾値、想定読者等)は確認質問を省略する。恒常的に使えそうな新しい設定を確認したら、利用者の同意を得て設定ファイルに保存する(初回セットアップは cpa-setup スキル)。
- **委譲の例外**: 対象が小さい場合(目安: データ数百件以下、文書数ページ、単一の軽い論点)は、サブエージェント委譲のオーバーヘッドの方が大きいため、メインで直接実施してよい。ただし品質工程(最終レビュー・引用突合)は省略しない。
- **Gotchas を育てる**: このスキルの利用中に新しい失敗・つまずきがあったら、下の Gotchas に追記する(CLI では直接編集、Cowork ではチャットで改訂を依頼するよう利用者に一言添える)。

## Gotchas(実際に踏んだ罠を追記して育てる)

- 前期数値が「組替後」か「組替前」かを確認せず前期比較すると、見かけの増減に振り回される。
- 月次データの税込/税抜、年次データとの整合(決算整理仕訳の反映有無)を最初に確認する。
- 回転期間等の比率は分母(期末残高か平均残高か)を統一する。前年と定義が違う比較は無意味。
- 乖離が「許容範囲内」でも、複数科目の小さな乖離が同方向に揃っている場合は合わせて評価する。
