# 有報サーチによる開示例検索

日本公認会計士協会(JICPA)の会員向けサービス「有報サーチ」((株)インターネットディスクロージャーが開発し、協会が同社と利用契約したもの)を Claude in Chrome で操作し、有価証券報告書等の**開示例**を検索・収集・整理するスキル。

## モデル振り分け

| 工程                                | 実行者                            | 理由                                        |
| ----------------------------------- | --------------------------------- | ------------------------------------------- |
| ①論点の把握・検索条件の設計         | メイン(高推論モデル)              | どの箇所をどの語で探すかが品質を決める      |
| ②ログイン・検索・本文取得           | メイン(ブラウザ操作)              | ブラウザのタブ状態は1つ。委譲すると競合する |
| ③大量本文の構造化抽出(多い場合のみ) | **doc-extractor(低コストモデル)** | 保存した本文から定型項目を抜き出すだけ      |
| ④事例の選別・比較・示唆             | メイン(高推論モデル)              | 基準への当てはめと「参考になる例」の判断    |
| ⑤一覧表・報告書の整形(必要時)       | **report-writer(低コストモデル)** | 整形のみ                                    |

## 前提

- 利用者が JICPA 会員で有報サーチの利用契約があること。
- Claude in Chrome が利用者の Chrome に接続されていること(使う前に `claude-in-chrome` スキルの手順でツールを読み込む)。
- **パスワード等の入力は Claude が行わない。** ログインは Chrome のオートフィル済みの状態で「ログイン」を押すだけ。オートフィルされていなければ利用者に手動ログインを依頼する。

## 手順

### ① 検索条件の設計(メイン)

利用者の依頼から次を決める。曖昧な点は重要なものだけ確認し、それ以外は既定値で進めて冒頭に明記する。

- **何の開示例か**: 論点(例: 本人代理人、のれん減損、ポイント、KAM)と、探す箇所(会計方針/注記/見積り/KAM/事業等のリスク等)
- **キーワード**: 開示で実際に使われる語にする(会計基準の用語、注記見出しの用語)。空白区切りで AND。同義語の並列は OR モード。除外語も使える
- **目次指定**: 箇所が決まっていれば必ず指定する(ノイズが激減する)。ラベルは `references/toc-labels.md` を参照、不明なら `YUHO.listToc()` で確認
- **絞込み**: 期間(既定=**提出日が直近1年**)、書類(既定=有報)、業種・市場・決算月・連結/非連結・会計基準(日本基準/IFRS等)・監査法人
- **件数の目安**: 最終的に示す事例数(既定 5〜10 社)。必要以上に本文を開かない

### ② ログインと検索(メイン・ブラウザ操作)

1. Chrome のタブ状況を確認し、新しいタブで `https://jicpa.or.jp/n_member/redirect.php` を開く。
2. JICPA の会員ログイン画面(sso.jicpa.or.jp)が出たら、ユーザーID・パスワードが**オートフィル済みであることをスクリーンショットで確認**し、「ログイン」を押す。ログイン済みなら会員マイページが表示されるので、そのまま次へ。
3. `https://www.hp.jicpa.or.jp/app_portal/action/initJicpaDbYuhoMain` を開き、**「有報サーチ」リンク**を押す。
   - 同じ枠内にある「**個人契約解除**」は絶対に押さない(契約解除の手続きが始まる)。
   - `find` の ref でのクリックは反応しないことが多い(2 回再現)。`zoom` でリンク位置を確認して**座標でクリック**する。
   - タブの URL が `jicpa.esper-search.com/ufosearch/default.aspx` に変わったことを確認する。
4. 有報サーチはフレーム構成で、画面操作より **JavaScript で操作する方が確実で速い**。`scripts/yuho.js` を Read し、その全文の末尾に呼び出しを付けて `javascript_tool` で実行する。一度読み込めば同じタブに `window.YUHO` が残るので、以降は呼び出しだけでよい(`typeof YUHO` が `undefined` なら再読み込み)。

```js
// 例: 小売業の収益認識注記でポイント/契約負債に触れた例を、スコア順に20件
await YUHO.search({
  keywords: 'ポイント 契約負債',          // 必須。空白区切り=AND(mode:'or' で OR)
  exclude: '',                            // 除外語
  tocLabels: ['収益認識関係（連結）'],     // 目次指定(ラベル完全一致。前方一致は末尾に *)
  // dateType: 'filed'(提出日・既定) | 'fiscal'(決算日)。from/to 省略時は直近1年
  from: '2025-07-01', to: '2026-06-30',
  industry: '6100',                       // 東証業種コード(references/toc-labels.md)
  accounting: '日本基準',                  // '日本基準'|'IFRS'|'SEC'|'日本基準以外'
  perPage: 20, sort: 'score', kwic: 40,   // sort: 'date_desc'(既定)|'date_asc'|'score'|'code_asc'|'code_desc'
})
```

主な関数(戻り値はすべてテキスト。失敗時は `error` を持つオブジェクトを返すか例外を投げる):

| 関数                           | 内容                                                                                       |
| ------------------------------ | ------------------------------------------------------------------------------------------ |
| `YUHO.search(opts)`            | 検索を実行し 1 ページ目を返す(`condition` 検索条件、`summary` 件数、`hits` 一覧)            |
| `YUHO.next()`                  | 次ページ(切り替わらなければ `error`)                                                       |
| `YUHO.open(no, maxChars=8000)` | 結果番号 `no` の該当箇所の本文を開いて返す(`chunks` 配列。`nextOffset` が null でなければ続きあり) |
| `YUHO.text(offset, len)`       | 直近に開いた本文の続き                                                                     |
| `YUHO.backToResults()`         | 検索結果一覧に戻る(`open` の後、次の `open` や `next` の前に必ず実行)                      |
| `YUHO.listToc(binder, filter)` | 目次ラベルの一覧(`[緑]` は XBRL 詳細タグの項目)                                             |

`opts` の全項目は `scripts/yuho.js` の `search` 直前のコメント参照(binder: 'ufo' 有報 / 'hanpo' 半期 / 'shihanki' 四半期 / 'rinpo' 臨時 / 'teisei' 訂正 / 'tousei' 内部統制 / 'tdnet_tanshin_pdf' 短信 等、exchange、fiscalMonth、consolidated、auditor、goingConcern)。`hits[].docDate` は「有報 決算日(提出日)」の形。

5. **検索条件の検証**: 戻り値の `condition`(画面の【検索条件】欄)を読み、指定した期間・目次・絞込みが全て反映されていることを確認する。反映されていなければ結果を使わない。
6. **件数の調整**: 件数が多すぎる(目安 300 件超。画面の表示可能件数は 300 件まで)なら目次・業種・期間で絞る。0 件なら語を開示の言い回しに変える、目次を外す、OR にする。
7. **KWIC で一次選別**: `hits[].kwic`(ヒット箇所前後の抜粋)と `section`(該当箇所)を見て、論点に当たる候補を選ぶ。同一社が複数行出るので社単位でまとめる。
8. **本文の取得**: 候補ごとに `YUHO.open(no)` → 必要なら `YUHO.text(nextOffset)` で続き → `YUHO.backToResults()`。長い箇所(監査報告書全体など)は `text()` で該当部分まで進める。

### ③ 構造化抽出(件数が多い場合のみ doc-extractor に委譲)

取得した本文が 10 社超などで多い場合だけ委譲する(少数ならメインで直接読む)。本文を作業フォルダ(スクラッチパッド)に会社ごとのテキストファイルで保存し、Agent ツールで doc-extractor に次の引き渡し資料を渡す:

```
目的: 有報サーチで収集した開示例から、比較表の材料を抜き出す
入力: <保存フォルダのパス>(1ファイル=1社。先頭行に 会社名/証券コード/書類/決算日/該当箇所)
抽出項目: <依頼論点に応じて列挙。例: 判断の要素/定量情報の有無/記載の粒度/基準への言及>
出力: 1社1行の表(上記項目+原文の該当文の引用)を <出力パス> に保存しパスを返す
禁止: 評価・優劣判断・要約による言い換え(原文の引用で示す)
```

### ④ 選別と分析(メインで実施 — 委譲しない)

- 依頼の目的(自社開示の文案検討/監査での比較/論点調査)に照らし、**参考になる例を選ぶ理由**を付ける(詳細な例、簡潔な例、業種が近い例、判断要素が明示された例など、タイプの違う例を揃える)。
- 書きぶりの共通点・相違点(記載項目、粒度、定量情報の有無)を整理する。
- 会計基準の要求事項に触れる場合は accounting-consult スキルの出典ルールに従う(基準名・項番号、必要に応じ standards-checker で突合)。

### ⑤ 出力

既定はチャットで次の形式(依頼があれば report-writer で docx/xlsx 等に整形):

1. **検索条件と件数**(`condition` と `summary` をそのまま。再現できるように)
2. **事例一覧表**: 会社名(証券コード)/業種・市場/書類・決算日/監査法人/該当箇所/要旨/選定理由
3. **原文抜粋**: 事例ごとに該当部分を引用(会社名・書類・決算日・箇所を明記)
4. **整理・示唆**: 共通点、バリエーション、利用者の目的に対する示唆

## 注意

- 有報サーチの利用規約上、サービスを**契約者以外の第三者に利用させることはできない**。成果物は利用者自身の業務用とし、原文の引用は必要な範囲に留め出典を明記する。
- 自動操作でも利用者の契約に基づくアクセスである。依頼に必要な範囲だけ検索・閲覧し、全件の機械的な連続取得はしない。自動操作の可否を含む利用規約の確認は利用者の責任である旨を、初回利用時に一言添える。
- 取得した本文は Claude(モデル)に送られて処理される。機密性の観点で問題がある使い方を利用者が想定していないか、必要なら確認する(公開済みの開示書類なので通常は問題にならない)。
- 開示内容は各社の判断によるもので、開示例であることは基準への準拠や十分性を保証しない。最終判断は利用者の責任である旨を付す。
- 操作は検索・閲覧のみ。設定タブの変更、ウォッチリスト登録、ログアウト、契約関連の操作は行わない(`yuho.js` のタブ切替も検索・検索結果・文書に限定している)。

## 共通運用ルール

- **設定ファイル**: 作業開始前に `${CLAUDE_PLUGIN_DATA}/config.json`(環境変数未定義なら `~/.claude/cpa-toolkit-data/config.json`)を読む。設定済みの項目(適用基準の既定、重要性方針、様式、閾値、想定読者等)は確認質問を省略する。恒常的に使えそうな新しい設定を確認したら、利用者の同意を得て設定ファイルに保存する(初回セットアップは cpa-setup スキル)。
- **委譲の例外**: 対象が小さい場合(目安: データ数百件以下、文書数ページ、単一の軽い論点)は、サブエージェント委譲のオーバーヘッドの方が大きいため、メインで直接実施してよい。ただし品質工程(最終レビュー・引用突合)は省略しない。
- **Gotchas を育てる**: このスキルの利用中に新しい失敗・つまずきがあったら、下の Gotchas に追記する(CLI では直接編集、Cowork ではチャットで改訂を依頼するよう利用者に一言添える)。

## Gotchas(実際に踏んだ罠を追記して育てる)

- **「Cannot access a chrome-extension:// URL of different extension」** でスクリーンショット・DOM 読取り・クリックが全て失敗する場合、他の Chrome 拡張機能がページに iframe を差し込んでいる。利用者に該当拡張の無効化(または「サイトへのアクセス: クリック時」)を依頼する。JICPA ポータルでは再読み込みで直ることもある。
- ポータルの「有報サーチ」リンクは `find` の ref クリックでは遷移しないことがある(2 回再現)。座標クリックで遷移した。
- 検索フォームの値を JS で設定するとき **`change` イベントを発火させない**。年や月の `change` でサーバー側の再描画が走り、月や目次指定が無言でリセットされる(決算日 4/1 指定が 7/1 になった)。`yuho.js` は書類種別の変更だけ先に `change` を発火(非同期ポストバック)→完了待ちしてから他を設定している。
- **並び順の選択肢は直前の検索の日付種別で変わる**(決算日で検索した後は「決算日／降順」、提出日で検索した後は「提出日／降順」)。固定値を入れると失敗する。`yuho.js` は画面にある方を選ぶ。
- 「目次選択」ボタンは別ウィンドウ(ポップアップ)を開き、Claude in Chrome のタブグループ外になって操作できない。`yuho.js` は同じ画面(`selectToc.aspx`)を非表示 iframe で開いてチェック→「設定」し、返ってきたコード(カンマ区切り)を `targetTocValue` に入れている。
- 目次は同時 10 項目まで、うち緑(XBRL 詳細タグ)は 3 項目まで。超えるとサイトが警告して目次コードが返らない。`yuho.js` は事前に数えてエラーにする。同じラベルが連結・単体の両方にある項目(例: 有報の「減損損失に関する注記 [緑]」)はラベル指定で両方チェックされ、2 項目と数えられる。
- 目次ラベルは長いと「...」で切り詰めて表示される。完全一致が面倒なら前方一致(末尾に `*`)を使う。ラベル末尾の「 [緑]」「 ≫」は付けても付けなくてもよい。
- KAM(監査上の主要な検討事項)を目次指定しても、ヒット箇所は「監査報告書≫当期連結財務諸表に対する監査報告書」全体として返る。`open()` 後に `text()` で KAM 部分まで読み進める。
- 半期報告書(hanpo)の目次は「(5号)」付き(旧様式)と無印が混在する。(5号)を指定すると 2024 年以降の新様式の半期報告書がヒットしないことがある。まず目次なしで検索し、`section` を見てから絞る。
- `javascript_tool` は戻り値に URL・クエリ文字列・長い英数字列があると `[BLOCKED]` に置き換え、長い単一文字列は約 1,000 字で切り詰める。`yuho.js` は本文・KWIC 中の URL を `[URL]` に置換し、本文を 700 字ごとの配列で返す。改造時も守る。
- 検索フォームは前回の条件を保持している。`YUHO.search()` は全項目を毎回上書きするが、手動操作した後は特に `condition` を確認する。
- 決算日基準で「直近1年」にすると、4〜6 月の実行では 3 月決算の最新有報が未提出で前期分も範囲外になりやすい。既定は提出日基準にしてある。
- セッションが切れると有報サーチの画面がエラーやログイン画面になり、`yuho.js` は「default.aspx ではない」エラーを出す。その場合は手順②の 1 からやり直す。
