# 財務デューデリジェンス

M&A等における対象会社の財務DD(正常収益力・ネットデット・運転資本等)を支援するスキル。

## モデル振り分け

| 工程                              | 実行者                             | 理由       |
| --------------------------------- | ---------------------------------- | ---------- |
| ①スコープ確認                     | メイン(高推論モデル)               | 判断       |
| ②外部情報の収集                   | **researcher(低コストモデル)**     | 検索作業   |
| ③開示資料・データルーム資料の読解 | **doc-extractor(低コストモデル)**  | 大量読解   |
| ④集計・調整計算                   | **data-processor(低コストモデル)** | コード実行 |
| ⑤分析・調整項目の識別             | メイン(高推論モデル)               | 中核的推論 |
| ⑥レポート整形                     | **report-writer(低コストモデル)**  | 整形       |
| ⑦最終レビュー                     | メイン+**reviewer**                | 品質担保   |

## 手順

### ① スコープ確認(メイン)

案件の性質(買収/売却側/資本提携)、対象期間(通常3〜5期+直近期中)、重点領域(収益性/財政状態/税務・人事等の隣接領域の要否)、入手可能な資料、報告書の想定読者・形式・期限を確認する。

### ② 情報収集・読解(低コストエージェント群に委譲)

- researcher: 対象会社・業界の外部情報(company-research スキルの調査項目に準じる)
- doc-extractor: 提供資料(決算書、内訳明細、契約、規程)からの数値・条件の抽出

### ③ 分析(メインで実施 — 委譲しない)

計算は data-processor に委譲しつつ、調整項目の識別・判断はメインで行う:

- **正常収益力(Normalized EBITDA)**: 非経常項目(一過性の損益、役員報酬の水準調整、関連当事者取引の時価調整、会計方針の差異)を識別し、調整後EBITDAを算定する。各調整に根拠と金額算定過程を付す
- **ネットデット**: 有利子負債に加え、デットライクアイテム(未払退職給付、リース債務、訴訟・保証等の偶発債務、設備投資の未払、配当未払等)の該当性を検討する
- **運転資本**: 月次推移から正常水準を分析し、季節性・異常月を識別する
- **その他**: 簿外債務の兆候、収益認識の妥当性、偶発事象、Change of Control条項(doc-extractor の抽出結果から)

### ④ レポート(report-writer → reviewer → メイン)

「エグゼクティブサマリー/調整表(根拠付き)/領域別の発見事項(事実→影響→示唆)/未解明事項とQ&Aリスト」の構成で整形させ、reviewer の独立レビューとメインの最終確認を経て納品する。

## 注意

- DD報告書は取引判断に直結するため、事実(資料の記載)と見解(調整の要否の判断)を明確に分離し、情報の制約(未提供資料・未検証事項)を必ず記載する。
- 価値評価(バリュエーション)そのものは本スキルの対象外。求められた場合は別途スコープを協議する。

## 共通運用ルール

- **設定ファイル**: 作業開始前に `${CLAUDE_PLUGIN_DATA}/config.json`(環境変数未定義なら `~/.claude/cpa-toolkit-data/config.json`)を読む。設定済みの項目(適用基準の既定、重要性方針、様式、閾値、想定読者等)は確認質問を省略する。恒常的に使えそうな新しい設定を確認したら、利用者の同意を得て設定ファイルに保存する(初回セットアップは cpa-setup スキル)。
- **委譲の例外**: 対象が小さい場合(目安: データ数百件以下、文書数ページ、単一の軽い論点)は、サブエージェント委譲のオーバーヘッドの方が大きいため、メインで直接実施してよい。ただし品質工程(最終レビュー・引用突合)は省略しない。
- **Gotchas を育てる**: このスキルの利用中に新しい失敗・つまずきがあったら、下の Gotchas に追記する(CLI では直接編集、Cowork ではチャットで改訂を依頼するよう利用者に一言添える)。

## Gotchas(実際に踏んだ罠を追記して育てる)

- EBITDA調整の二重カウント(例: 役員報酬調整と関連当事者取引調整で同じ取引を両方調整)が起きやすい。調整表で取引単位の重複を確認する。
- 月次データは決算整理仕訳(賞与引当、減価償却の月割差異等)が未反映のことが多い。年次との突合で調整の要否を確認する。
- 運転資本の正常水準分析で、M&A発表後や期末の一時的な入出金を含めたまま平均を取らない。
